# SubGauge 验收摘要

整理日期：2026-10-02；桌面验收基线：0.1.5。本页区分既有实测与当前源码检查。自动回归、隔离原生 API、用户实际操作和部署核对分别记录，不能互相替代。

## 公开材料整理后的检查

当前源码的 `npm run verify` 通过：Vue/TypeScript 类型检查、生产前端构建、202 项布局回归、Rust 格式、严格 Clippy 和 47 项 Rust 回归。`npm audit` 没有报告已知 npm 依赖漏洞；此结果不覆盖 Rust 依赖或全部安全问题。

当前文件已检查版本一致性、文档本地链接和隐私模式，未检出真实站点、个人邮箱或高置信度凭据模式。仓库已重新初始化，首次提交仅包含审查后的文件；旧 Git 与内部记录备份位于项目外。截图仅使用明确标注的示例数据。

本次源码清理不代表已重新构建或安装二进制，也没有重做真实站点与原生桌面验收。CI 配置已整理，远端尚未运行。

## 代码审查待处理项

- 从筛选后的请求记录或后续页返回概览时，旧记录可能暂留；若概览读取失败，还会继续显示旧结果。应按查询上下文隔离或清空。
- 保存账号显示设置并返回账号管理时，切页监听会清空刚设置的成功提示。
- 保存账号偏好等待缓存锁期间，同账号重新登录可能替换运行时；提交偏好前缺少运行时身份校验，可能使默认范围与当前范围不一致。

前两项已通过真实 Vue 页面、官方 Tauri IPC 模拟和无头 Edge 的示例场景复现：概览读取延迟及失败后仍能看到上一页的记录；保存偏好成功并返回账号管理后没有成功提示。第三项已通过纯夹具复现：持有旧缓存锁、保存月范围、替换同账号运行时、释放锁，返回默认范围为月而当前范围仍为今日。

临时诊断脚本与测试均已清理，未修改生产逻辑。这三项仍待修复并保留回归，不把现有测试通过理解为它们已经解决。

## 验证环境

主要实测环境为 Windows 10 Pro x64（19045）、已安装 WebView2、150% 实际系统缩放。Windows 11、其他实际 DPI 和多屏尚未完成验收。浏览器检查中的 100%～200% 为模拟像素比例，不表示对应 Windows 系统 DPI 已通过。

## 个人接口与统计核对

| 部署 | 既有核对范围 |
| --- | --- |
| 部署 A：管理员账号 | 邮箱登录、个人余额与用量接口、加密会话重启恢复，以及已结束日期的汇总和完整分页明细 |
| 部署 B：普通用户账号 | 邮箱登录、个人余额与用量接口，以及已结束日期的汇总和完整分页明细 |

两部署分别按同一账号、时区和范围核对，费用、四项 Token 及加权缓存率与完整明细一致；余额更新后与个人接口一致。管理员核对使用个人接口，没有以全站统计代替个人用量。样本各只有一个不同 Key，不能据此宣称实际多 Key 已验证。

活跃日期存在新增请求和采样时间差；服务端没有提供多个接口的严格事务快照。普通用户结果不能推导为所有定制部署均受支持。真实站点启用 TOTP、验证码挑战及延迟落库场景仍待验证。

## 持续运行与资源

0.1.4 的两个账号持续运行观察约 60 分钟，应用保持响应，没有观察到持续 CPU 忙循环或崩溃；后半段内存增速放缓，但均值仍有增长。观察期间包含其他构建和检查，没有独立确认用户全程无操作，因此不是严格纯空闲基线，也不能证明长期没有泄漏。

该记录不能沿用为 0.1.5 的长期稳定性通过。资源观察已结束，本次整理没有新增或延长采样。进程树工作集可能重复计算共享页，不能直接当作独占内存。

## 实现边界

- 默认账号统计时区为 `Asia/Shanghai`，可修改；服务端图表分桶标签时区仍未验证。
- 汇总边界明细和 Key 分析最多读取 5,000 条、最多两次覆盖确认；不完整时明确标记，不能作为最终总计。请求列表采用独立分页，可翻到该数量之后。
- 滚动列表翻页沿用固定范围，上下文有效 60 秒；过期或记录变化时需刷新第一页。
- 图表按需读取，缓存最多 5 分钟；强制刷新不越过账号限流等待期。本月汇总不周期拉取整月明细。
- `Retry-After` 仅支持整数秒；请求不主动取消，通过账号、运行时、范围和代次拒绝过时结果。
- 分发未签名；没有套餐结转、跨站费用合计、自动更新、云同步或全量历史数据库。

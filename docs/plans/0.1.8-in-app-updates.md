# 0.1.8 内置更新计划

日期：2026-10-03。状态：源码、回归、远端 CI、正式附件与更新清单发布完成；本版包含 0.1.7 的窗口改进，实际设备和真实账号升级验收继续按原清单执行。具体公共渠道结果、已通过与未执行项见 [验证记录](../validation.md)。

## 用户流程

应用设置显示当前版本、安装版/免安装版、预览渠道及更新状态；托盘提供“检查更新”。启动后延迟检查，随后最多每天一次，可关闭自动检查。后台只检查，不下载或安装，也不在浮窗增加常驻内容。

用户主动检查后可查看版本和更新说明。安装版点击下载，显示进度；完整下载并验证签名后才提供“安装并重启”，需明确确认。支持稍后与跳过此版本，手动检查仍可查看被跳过版本。网络、签名、保存和安装器启动失败分别明确报告，可重试，失败不清除账号或主动卸载旧应用。

免安装版和开发版不调用安装器。免安装版通过验证过的项目 Release 链接取得 ZIP，暂不实现运行中替换 EXE，不默默改变分发类型。开发版显示限制，仍可检查更新。

## 原生与分发

使用 Tauri 官方 updater 2.13.1，与当前 Tauri 2.12.1、Rust 1.90 声明兼容，依赖锁定。更新操作和状态由 Rust 单例服务管理，窗口共用，前端不能传入任意更新地址、公钥、安装参数或降级规则。状态具有递增 revision，旧响应不能覆盖当前阶段；重复操作合并或明确拒绝。

预览渠道使用项目 `updates/preview.json` 的静态清单，下载指向同一 GitHub 仓库的固定版本 Release。生产仅允许 HTTPS；检查与下载使用独立客户端，不带 Sub2API 会话。公共更新公钥随源码分发，私钥和密码存储在仓库外，密码由当前 Windows 用户 DPAPI 保护；签名与包版本一致性必须核对。该签名不同于 Windows 证书，当前不购买证书。

更新偏好、检查时间及安装结果记录在独立版本化配置，采用原子写入，不改写账号配置格式。下载期间同步正常继续；安装前设置操作屏障，拒绝新账号修改和后台同步，等待已开始的核心操作完成；窗口必须结束拖动/缩放，确认账号及窗口保存成功后才调用安装器。准备失败返回下载完成状态，释放屏障，恢复正常使用。安装器启动成功后交由官方更新流程退出和重启，重新启动检查预期版本。

安装版通过 NSIS 更新模式覆盖当前安装位置，实际路径保留需隔离验收；数据始终在当前用户数据目录。更新清单与签名由发布工具生成，签名或清单缺失时禁止准备可更新的公开版本。CI 普通检查不拥有私钥，也不自动公开 Release。公开发布以及更新渠道生效属于完成候选核对后的最终步骤。

## 验证顺序

1. 保留更新状态、重复操作、偏好持久化、版本比较、地址限制和失败恢复的回归。
2. 浏览器模拟验证状态、进度、无总长度、安装确认、错误重试、过期响应、免安装限制；复跑原布局和详情回归。
3. 使用独立签名夹具与隐藏原生应用验证真实插件检查、下载、签名拒绝及更新准备，不读取日常账号。
4. 在独立标识、配置目录和安装位置验证安装版升级、重启与旧设置保留；不足的设备条件明确记为未执行，不操作日常安装实例。
5. 运行类型、格式、严格 Clippy、Rust 回归与构建；核对安装包、ZIP、声明、签名、更新清单及 SHA256；记录新结果和未执行项。

实际双屏、混合 DPI 和 Windows 11 验收仍待对应设备完成。旧版没有更新模块，第一次升级到带更新功能的版本仍需手动安装。

# 0.1.7 置顶入口与多屏拖动方案

设计日期：2026-10-03。状态：源码与本地候选包已完成，自动回归及隔离原生冒烟通过；实际双屏和升级尚待验收。本文件保留设计与验收要求，已执行结果见 [验证记录](../validation.md)。

## 问题与依据

0.1.6 的置顶开关位于“详细用量 → 应用设置”，浮窗顶部齿轮打开的是当前账号的显示设置。隔离示例页面已确认开关可见，并可保存开、关状态；这项浏览器检查不等于原生置顶效果的验收。

用户报告另一台双屏电脑无法把浮窗拖到另一块屏幕。`windows.rs` 的 `on_moved` 每次将完整窗口限制在 `current_monitor` 的工作区。锁定的 Tao 0.37.1 在 Windows 上使用 `MonitorFromWindow`，该接口按窗口与屏幕的最大相交面积选择屏幕。小步拖过接缝时窗口仍属原屏，立即被拉回。相邻屏幕的几何模拟已复现这一阻断，实际双屏硬件仍待验收。

现有 DPI 处理、菜单扩窗、布局请求和托盘恢复也会调整窗口。只删除一个移动回调中的校正，不能保证拖动期间没有其他路径把窗口拉回。

## 交互设计

### 置顶快捷入口

小卡片底部右侧采用“置顶图标＋展开/收起”的排列；底部左侧继续显示同步状态。将新增操作放在底部，保持顶部账号名称与统计范围的空间，卡片不增加一行。

| 状态 | 显示与操作 |
| --- | --- |
| 已置顶 | 图钉使用主题强调色，`aria-pressed=true`；悬停提示“取消置顶” |
| 未置顶 | 使用中性图钉取消图标，`aria-pressed=false`；悬停提示“置顶浮窗” |
| 切换中 | 只暂时禁用置顶按钮，避免重复提交；后台用量同步继续 |
| 失败 | 明确显示失败，重新读取实际状态；不把操作失败显示为已成功 |

按钮使用约 28 个逻辑像素的命中区域，键盘可聚焦并以 Enter/空格操作；浅色、深色均能区分状态，不仅依赖颜色。未连接账号的欢迎卡片也提供该入口。

托盘增加可勾选的“浮窗置顶”，在浮窗被其他窗口遮住时仍可操作。详情窗口“应用设置”的开关保留，并说明它控制浮窗。三个入口共享同一应用设置，切换账号不改变置顶，重启恢复最后成功保存的值。

浮窗原有齿轮保留“当前账号显示设置”的职责，增加明确的悬停提示。置顶只控制浮窗，不将详情窗口一起置顶；取消置顶后按 Windows 普通窗口层级显示。

快捷切换只提交置顶字段，不发送前端持有的整份旧设置，避免覆盖别处刚修改的主题或刷新间隔。设置页保存只提交用户改动的字段；未改字段跟随外部更新，同一字段编辑冲突需提示重新确认。原生窗口与配置都成功后才广播完成状态。

### 跨屏拖动

继续使用现有顶部拖动柄，用户不需要先选择目标显示器。

1. 按下拖动柄后关闭账号菜单并完成菜单尺寸恢复，再记录本次拖动起点。
2. 拖动中允许浮窗经过两屏接缝，也允许临时跨在两块屏幕上；所有程序布局路径都暂停位置校正，不与鼠标抢位置。
3. 结束拖动后确定落点屏幕，在该屏幕内执行一次最终尺寸、位置校正，再保存位置。
4. 取消拖动、启动失败或窗口关闭都必须结束对应手势；迟到的回调不能结束下一次拖动。

屏幕选择规则保持确定性：优先选择最终窗口与显示器相交面积最大的屏幕，沿用 Windows 的通常行为。相交面积相同时优先使用结束时指针所在的候选屏幕，再使用本次起点屏幕；仍无法区分时按屏幕坐标排序选择。完全不与任何屏幕相交时使用最近的显示器。最终位置按该屏的工作区调整，避开任务栏。重启恢复使用保存位置与现有屏幕的相交或最近关系，不用启动时的鼠标位置。

最终让完整卡片留在一块屏幕的可用工作区，避开任务栏；调整采用所需的最小位移。窗口大于工作区时先限制实际尺寸，保证顶部操作可见，展开内容按现有规则局部滚动。拖动途中没有自动吸附，松手时才完成必要校正。

显示器集合必须逐块处理，不能只用所有屏幕的外包矩形：上下错位、竖屏和 L 形布局之间的空白区域不是可用桌面。位置允许负坐标，支持副屏在主屏左侧或上方。

### 展开、收起与位置

| 用户动作 | 结果 |
| --- | --- |
| 原地展开后收起，没有手动移动 | 按已有约定恢复展开前的小窗位置与尺寸 |
| 展开状态手动移动，再收起 | 小窗留在移动后的屏幕，以最终展开窗左上角为新位置基准，按小窗尺寸校正 |
| 展开状态只改变大小 | 保留两态各自尺寸规则，不当作一次跨屏位置移动 |
| 打开和关闭账号菜单 | 临时扩窗不改写用户尺寸或移动基准 |
| 新位置保存后重启 | 在原屏仍连接时恢复新位置；位置无效时恢复到最近可用屏幕 |

只有一次手动移动最终改变了位置或屏幕，才更新收起位置基准；自动展开避让、菜单调整与 DPI 回调不能冒充用户移动。

### DPI 与显示器变化

用户保存的宽高继续使用逻辑像素。跨 100%、125%、150%、200% 的屏幕时，Windows/Tao 的原生 DPI 处理继续工作；SubGauge 不将系统产生的物理尺寸变化保存成一次手动调尺寸。

拖动期间收到的内容高度与应用布局请求合并保留最新值，暂停主动改位置、改尺寸；系统必要的 DPI 处理保留。手势结束后根据目标屏幕的最终缩放、最新内容和已保存逻辑尺寸统一计算，避免“旧 DPI 回调”将窗口移回原屏。短小屏幕上的临时尺寸限制不覆盖用户偏好。

副屏断开、工作区改变或睡眠恢复后重新获取屏幕集合。若浮窗位置已无法操作，移动到最近仍连接的显示器并限制在工作区；隐藏的浮窗只修正内部位置，不自行弹出。托盘“显示浮窗”和重复启动也检查有效屏幕，作为恢复入口。显示变化通知用于触发检查，但不能假定一次 `WM_DISPLAYCHANGE` 覆盖所有热插拔情形；启动、恢复和显示浮窗时都要重新读取屏幕信息。

## 实现安排

### 原生移动状态

把拖动交由受限的原生 `start_float_drag` 命令管理，先记录手势与代次，再调用系统拖动。现有缩放逻辑继续保留，但移动、缩放和程序布局需区分来源。

锁定的 Tauri 2.12.1 公共 `WindowEvent` 没有移动开始/结束事件；`start_dragging` 返回也不表示用户已松手。实施时优先验证浮窗专用的 Windows 移动/缩放消息监听，以 `WM_ENTERSIZEMOVE`、`WM_EXITSIZEMOVE` 判断系统手势生命周期，覆盖松手、Escape 和失去捕获。监听不拦截鼠标，不修改全局输入，不接管 Tao 的 DPI 处理。

计划仅对浮窗 HWND 使用 `SetWindowSubclass` 观察消息，在窗口所属 UI 线程安装和移除，并继续转发 `DefSubclassProc`；窗口销毁时清理引用。锁定的 `windows-sys` 0.61.2 将这组 API 放在 `Win32_UI_Shell` feature，实施时核对 feature 与导入位置，不升级依赖以寻找未公开的框架事件。

原生回调只记录状态并投递后续任务，保留原消息链；不在回调内持锁调用框架窗口 API、写配置或访问网络。Wry 最外圈拖边会绕过前端命令，使用原生方向及 HWND 起始矩形轻量采纳该手势；系统菜单的移动与大小调整通过 `WM_SYSCOMMAND` 采纳。元数据只用非阻塞短锁，普通移动、缩放和结束时共用同一代次。菜单的临时高度不能由该入口保存为用户偏好。监听的安装、销毁和失败清理须经过隔离原生检查。

实现使用系统结束消息，移除旧物理左键轮询。仅对已发出但未进入系统循环的手势保留一次 2 秒兜底；已开始的手势不被超时强制结束，不引入空闲时常驻轮询。

`on_moved`、`layout_request`、DPI 回调、菜单恢复、托盘恢复共用手势状态：移动中只记录待处理布局；结束后校正、更新两态位置基准并保存一次。程序自动位置修正不得递归触发新的移动保存；手势代次与现有布局代次共同拒绝旧任务。

### 设置一致性

原生层统一串行处理浮窗置顶、设置字段变更和持久化，使用最新设置做局部更新。窗口操作失败时不提交新设置；落盘失败时恢复本次窗口变更并报告错误，恢复也失败时读取实际状态并明确标记未保存，不能默默宣称成功。

不在持有核心状态锁或布局锁期间等待 UI 线程，保持现有锁序安全约定。设置成功后发布最新状态到浮窗、详情和托盘；迟到响应不能将按钮或勾选状态恢复成旧值。

## 开发顺序与交付

| 步骤 | 可查看成果 | 完成条件 |
| --- | --- | --- |
| 1. 跨屏回归和原生消息探针 | 接缝阻断的失败回归、隔离窗口手势记录 | 区分开始、移动、DPI、结束和取消；不读取真实账号 |
| 2. 修复原生移动 | 可在屏幕间移动的隔离候选应用 | 共享边界不拉回；松手校正；展开移动收起留在新屏 |
| 3. 置顶快捷入口 | 浅色/深色卡片、托盘和设置联动 | 原生置顶效果、保存恢复、失败与并发均符合规则 |
| 4. 原生与双屏验收 | 检查记录和两机反馈 | 完成下列受影响项，未执行环境明确注明 |
| 5. 0.1.7 候选分发 | 安装版、ZIP、校验文件与发布说明 | 统一检查、CI、实际包内容和升级路径核对；确认后再公开发布 |

先修多屏基础，再接快捷入口，防止一边调整界面一边掩盖窗口问题。无需重新发起长时间资源观察；只检查新消息监听、手势任务是否结束、空闲后有无新增忙循环或重复工作。

## 重点验收

| 类别 | 必须覆盖 |
| --- | --- |
| 单屏边缘 | 四边与四角松手后可操作；任务栏在底部、顶部或侧边时使用工作区 |
| 相邻双屏 | 向左、右、上、下慢拖过接缝；快速跨屏；相交面积相同和指针靠近接缝时落点选择确定 |
| 复杂布局 | 副屏负坐标、上下错位、竖屏、L 形空白区；不把空白区当作可用工作区 |
| 混合 DPI | 双屏至少覆盖相同缩放及 100%/150% 或 100%/200%；逻辑尺寸、拖动锚点与文本正常 |
| 两态与菜单 | 收起态和展开态跨屏，移动后收起、重新展开、开关账号菜单、调尺寸与恢复默认 |
| 手势与竞态 | 极短拖动、零位移、移走再移回、Escape、失去捕获、启动失败；交换主鼠标键、关闭“拖动时显示窗口内容”；拖动中同步改变内容，旧布局或 DPI 回调迟到 |
| 恢复 | 副屏断开、主屏改变、睡眠恢复、隐藏期间变化；托盘与重复启动可找回浮窗 |
| 置顶 | 置顶/非置顶与普通窗口实际层级；三入口一致；切账号、重启、无账号、快速点击与保存失败 |
| 设置并发 | 快切置顶不覆盖主题或同步间隔；外部切换不被详情里的旧表单覆盖；旧响应不回退状态 |
| 分发与升级 | 0.1.6 → 0.1.7 保留 D 盘安装位置、账号和设置；两种分发单实例；附件声明、版本和 Hash 一致 |

永久回归保留共享边界、负坐标、屏幕选择、DPI 代次、移动后收起、置顶字段并发与失败恢复。已有类型检查、布局/详情回归、Rust 格式、严格 Clippy 和业务回归继续运行。

几何回归和浏览器模拟仅验证对应规则，不算实际多屏通过。第一轮使用隔离示例窗口验证单屏；真实双屏部分需要用户另一台电脑安装候选版本后验收。记录显示器相对排列、分辨率、缩放和结果，不收集真实用量或凭据。
